Abstract—Transformer-based Large Language Models (LLMs)
demand large weight capacity, efficient computing, and high
throughput access to large amount of dynamic memory. These
challenges present great opportunities for algorithmic and hardware innovations, including Analog AI accelerators. In this paper,
we describe recent progress on Phase Change Memory-based
hardware and architectural designs to address the challenges for
LLM inference.
Index Terms—Analog In-Memory Computing, Phase Change
Memory, 3D AIMC.

I. I NTRODUCTION
Transformer-based language models have gained significant
traction in real-world artificial intelligence (AI) applications
since the inception of the “Transformer” attention-based network architecture [1]. These models have evolved over time
from encoder-only architectures for language embedding and
language classification, to encoder-decoder architectures for
machine translation and question answering, to the decoderonly architecture predominantly used for Large Language
Models (LLMs) [2].
As with earlier types of Deep Neural Network (DNN)
models, empirical evidence has shown that larger Transformer
models, with wider and/or more layers, achieve higher accuracy across different types of benchmarking tasks, such as
language modeling, reasoning, and more. As a result, the
number of Transformer model parameters has been growing
at 8x every 2 years, far outpacing both hardware memory
capacity growth and Moore’s Law. In order to meet the
growing compute demands, these massive DNN workloads
are often split across a large number of workers residing on
different chips, cards, or even data-center racks. All this scaleout implies yet more energy dedicated to data communication,
on top of the memory-to-CPU communication required by
the Von Neumann architecture, rather than to actual compute.
Another challenge associated with LLM workloads is the fastgrowing demand for longer sequence- or context-lengths, from
hundreds to many thousands if not millions of language tokens.
Several algorithmic improvements have been developed
to address these performance bottlenecks, especially during
model inference. Mixture of Expert (MoE) models [3] replace single, large, fully-connected weight-layers with multiple
smaller “experts,” allowing a router to select only a subset
of active weights during inference time. This allows the

models to contain a large number of weights and thus offer
a wide range of capabilities, while limiting the hardware
costs during inference. Alternative network architectures to
the traditional Multi-Head Attention (MHA) are also actively
being explored to reduce the hardware costs of attention
compute. Grouped Query Attention (GQA), used by most large
Llama models [4], shares a single Key and Value vector across
a group of attention-heads (each with its own Query vector),
which reduces the size of the KV-cache that must be saved
for subsequent token generation. Multi-head Latent Attention
(MLA), used by Deepseek-v3, utilizes compression to further
reduce KV-cache sizes [5]. State-space models (SSMs), such
as Mamba [6] or Bamba [7], replace all or most MHA layers
with recurrent layers to collapse one sequence dimension into
a fixed size vector, resulting in savings for compute time, onchip memory, and KV-cache.
II. A NALOG I N -M EMORY C OMPUTE (AIMC)
Another path to alleviate the growing data communication
for LLMs is to apply Analog In-Memory Compute (AIMC) to
perform matrix-vector multiplication (MVM) at the location of
the weights. AIMC maps DNN weights onto memory device
conductance or charge and takes advantage of Ohm’s Law
and Kirchhoff’s Law to compute MVMs at the location of
the weights in an analog fashion [8]. The main advantages of
AIMC lie in the high-density model-weight storage that leads
to high area efficiency (T OP S/mm2 ) and the more energyefficient multiply and accumulate in analog (T OP S/W ).
AIMC can be implemented in various ways, for example, using
volatile memory [9] or non-volatile memory (NVM) for weight
storage; storing one or multiple bits of weights per memory
device; and reading memory arrays using analog read voltages
[10] or a constant voltage with analog durations [11]. Among
these implementation options, AIMC with NVM is best suited
for keeping static DNN weights on-chip for extended period
of time and hence eliminating data transfer for model weights.
Several NVM has been used to demonstrate AIMC, including
phase chase memory (PCM) [12], [13], resistive random
access memory (ReRAM) [10], magnetoresistive random access memory (MRAM) [14], electrochemical random access
memory (ECRAM) [15], optical memory [16], NOR [17] and
NAND [18] flash memory. Keeping the architecture “weight

The first chip [12] includes 64 AIMC tiles and global digital
compute units at the center of the chip for complex operations,
such as activation functions and operations for Long-ShortTerm Memory (LSTM). The tiles consist of 256 × 256 logical
arrays with Current-Controlled Oscillator (CCO)-based ADCs
and local digital compute at each tile for scaling and ReLU
operations. The smaller tile size offers flexibility and high
array utilization for mapping convolutional neural networks
(CNNs) and smaller DNNs. In addition to demonstrating
image classification and image captioning, the chip was also
used to verify AIMC accuracies of base-calling DNNs for
genome sequencing [20].

next tile. DNNs with only fully-connected (FC) layers and

IV. AIMC FOR T RANSFORMER - BASED LLM S
The first challenge in using AIMC for LLMs is to confirm
that high DNN model accuracies can be maintained despite the
presence of AIMC non-idealities such as noise and conductance drift. To study networks well beyond the scale of current
hardware implementations, the AIHWKit [23] and AIHWKitLightning [24] were developed to model AIMC for DNNs
and enable hardware-aware (HWA) training [25]. AIHWKitLightning is a simplified and accelerated version to support
HWA training of LLMs. A RoBERTa model that included
HWA noise during pre-training demonstrated iso-accuracy on
the GLUE benchmark [24]. To study the impact of posttraining optimization techniques, we used the full AIHWKit
to study the accuracy and noise-resilience of OPT, Llama, and
Mistral models ranging from 2.7-13B weights [26].

The second challenge is to scale up the AIMC architecture
to handle the large number of LLM weights. Volatile memorybased AIMC can potentially utilize wafer-scale technologies
[27] for extreme capacity scaling. Larger tile sizes usually
leads to higher memory array density and energy efficiency,
but will be limited by IR-drop considerations as the long
bitlines accumulate more and more read-current.
NVM technology has great potential for density scaling to
host as many weights on one chip as possible. NVM-based
AIMC has an additional knob to scale up memory capacity
in 3D. Unlike in a fully 2D system, where each tile can have
its dedicated peripheral circuitry, multiple tiers in a 3D tile
can share input and output periphery, therefore allowing MAC
to be computed in a One-Tier-at-a-Time (OTT) fashion, as
shown in Figure 2. This makes the 3D AIMC system Fully
Weight Stationary (FWS), and opens up the prospect for a
“Fully Unrolled” system in which each layer has its own set of
Tiles, allowing the entire workload to be fully-pipelined [21].
Compared to a Partially Weight Stationary (PWS) system,
where weights are constantly reloaded from DRAM or SRAM,
3D AIMC maintains the more compact chip area without
incurring the energy and latency for weight reloading. The
3D architecture is especially suitable for MoE models. By
mapping experts in an MoE to different tiers of the same tile,
all the experts remain weight-stationary, and data-vectors can
be predictably delivered to the same Tile independent of which
expert they need to address [28].

For the token-generation phase of a decoder-base model,
attention compute scales as O(s), but requires access to the
Key and Value vectors from all previously-computed sequence
tokens, known as the KV-cache. When KV-cache size exceeds
on-chip cache capacity, data needs to be loaded repeatedly
from off-chip, creating a memory bottleneck. Worse yet, the
arithmetic intensity – the number of compute operations performed per byte retrieved from memory – is very low, leading
to inherent energy inefficiencies. In both pre-fill and generation
phases, when sequence length s becomes excessively long, the
attention part of the Transformer workload becomes a serious
hardware bottleneck.
These issues apply to both GPU-like digital accelerators
and AIMC, because self-attention matrices are computed in
digital hardware even in an AIMC system. This is because
self-attention compute involves MVMs between two dynamically computed matrices that are determined by the user
input. Unlike the static weights, dynamic activations are not
well-suited for NVM-based AIMC due to write speed and
endurance limitations. While volatile-memory-based AIMC
can potentially be used for self-attention compute, its limited
memory capacity usually prevents static mapping of model
weights, resulting in the requirement for very large chip area
or model weight transfer from DRAM.

V. C ONCLUSION
NVM-based Analog In-Memory Compute (AIMC) is a
promising candidate for serving Large Language Model
(LLM) inference workloads. MAC-level and system-level
AIMC has been demonstrated in hardware, up to the scale
of tens of millions of model-weights. We address AIMC
accuracy for LLMs by conducting hardware-aware pre-training
and post-training optimizations using AIHWKit. Architecture
analysis shows that AIMC scale-up to support LLMs requires
technology scaling, memory density scaling, custom digital
compute hardware, and improved LLM network architectures,
especially for self-attention compute. Continued algorithmhardware co-optimization will be key to improve hardware
efficiency.
